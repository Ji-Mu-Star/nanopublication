# pdf-parse@2.0.0 实测记录

记录日期：2026-11-26。以下均为本次开发中实际执行的测试，不是平台固定案例结果，也不代表正式评分。

## 1. 单元与合成 PDF 集成测试

执行命令：

```bash
python3 -m unittest discover -s tests -p 'test_*.py' -v
```

最终结果：**15 项测试全部通过（OK）**。覆盖：

- `case_id` 值与类型透传、严格契约额外字段拒绝、契约必填字段检查；
- 成功状态的逐页覆盖要求、章节/段落交叉引用、重复 ID；
- 表格合并网格重叠、Markdown 与 `cells[]` 数值不一致；
- OCR 纠正缺少改前/改后记录、正文不在布局证据中的模板内容；
- 同一首行被拆分块的排序、极端侧边窄高块的边注候选识别；
- 合成双页 PDF 的通栏标题/摘要 → 左栏 → 右栏顺序和重复页眉候选。

测试 PDF 由 `tests/make_synthetic_pdf.py` 生成，全部文字为 synthetic，不含正式案例内容。

### 实际失败与修复

首轮 13 项测试有 2 项失败：表格一致性函数未接入总校验流程，导致 Markdown 错误和网格重叠未触发。将 `check_table` 接入 `cross_checks` 后重跑通过，没有删除或放宽测试断言。随后增加 2 项真实 smoke test 暴露问题的回归测试，最终共 15 项。

## 2. 公开真实科研 PDF smoke test

输入：公开科研 PDF（arXiv:1810.04805），16 页、A4、未加密。该文件仅用于本地开发测试，未打包进 Skill 资源。

执行命令：

```bash
python3 scripts/extract_pdf.py /tmp/pdfparse-real.pdf /tmp/pdfparse-real-layout.json
pdftoppm -f 1 -l 1 -singlefile -png -r 100 /tmp/pdfparse-real.pdf /tmp/pdfparse-real-page1
```

最终结果：退出码 0；16 页均取得文本层内容；无空文字层页；修正后输出 584 个正文候选块；PDF SHA-256 为 `5692a5514787a8c6727b4ff3b726a3385798bc68e12138d1d4af83947e2acf6e`。

首轮首页检查暴露两个问题：作者姓名被 Poppler 拆块后，整块最小 x 坐标导致同一首行顺序不合理；左侧竖排 arXiv 水印进入正文候选。为此新增首行坐标排序和“极端侧边窄高块”边注候选规则。修正后首页前六块依次是标题、第一作者、其余作者/单位、Abstract、摘要首段、摘要次段；竖排水印转为 `margin_note_candidate`。

**边界**：该 smoke test 证明脚本能在一份真实 16 页论文上运行，并完成了首页页图对照；未对 16 页逐块建立人工金标准，因此不据此声称全文阅读顺序或字段准确率达到某个数值。

## 3. 历史平台反馈与本次改动关系

v1.0.0 的平台提交记录 112551 返回总分 53，判官总结为“Partial credit — push your agent for a more complete, genuinely-derived solution.”平台未提供逐项分数，故不能据此断定某一维度具体失分。

v2.0.0 将这条反馈转化为可执行约束：真实 PDF 坐标提取、来源哈希、逐页覆盖台账、正文布局证据回溯、契约优先校验和可重复测试。其他九项不足来自对 v1.x 文件与运行契约的静态审计。v2.0.0 的正式平台结果以新提交实际返回为准，本报告不预测分数。
